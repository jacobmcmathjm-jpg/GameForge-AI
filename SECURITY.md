# ForgeCore Security Model

## Invariants

- ForgeCore runs as a normal user; administrator actions are unsupported.
- Local file tools are confined to one configured workspace.
- Paths are fully canonicalised. UNC/device paths, traversal outside the root, and reparse-point/symbolic-link escapes are rejected.
- Reads require `Read`; mutations require `Write`; web acquisition requires `Network`; processes require `Execute`. `Administrator` is always denied.
- Commands are executable-plus-argument templates from an explicit allow-list. No shell is involved (`UseShellExecute=false`). PowerShell, `cmd`, installers, registry tools, and arbitrary executables are not enabled by defaults.
- Every proposal, policy decision, user decision, execution, and result is appended to the local audit database and structured log.
- Stop cancels the active task. Emergency Stop cancels the application-wide token and permanently disables further actions for that process.
- Session authorization is optional, in-memory, time/action limited, and bound to one exact project. It is consulted only after ordinary policy validation and never includes `RunCommand`, arbitrary writes, non-CC0 assets, another project, or `Administrator`; Emergency Stop revokes it.
- Passwords, API keys, tokens, and browser credentials must never be placed in the SQLite database or logs.
- Optional cloud 3D generation reads its key only from the configured user environment variable. The key is sent only as the fixed provider's Bearer header and is never included in prompts, tool results, manifests, configuration, logs, or SQLite.
- Every cloud-generation request requires explicit one-action approval and is excluded from session authorization. The dialog shows the full outbound prompt, provider/model, target project, possible credit use, and quarantine boundary.
- ForgeCore never downloads models. When LLamaSharp is explicitly enabled, it loads only the configured local `.gguf` file; UNC/device paths are rejected.
- Model output is untrusted even when JSON-grammar constrained. Duplicate or unknown fields, unknown tools, extra arguments, excessive actions, malformed JSON, oversized output, and model-supplied permission fields are rejected.
- Every replan is treated as new untrusted model output and passes through the same parser, aggregate action limit, security policy, approval flow, and audit trail. Tool observations are explicitly marked untrusted in the local-model prompt and character-bounded.
- Successful, policy-denied, and user-rejected actions cannot be silently repeated within one task. Failed executions are not automatically retried except bounded passive asset transfer attempts; the model may propose a failed call again after observing its error.
- Reaching the planning limit normally fails the task. If a dedicated `.NET build` or test already succeeded, ForgeCore may complete with an explicit limit notice; any later denied calls remain visibly blocked and audited and are never treated as executed.
- Model files are parsed by a native backend. Use GGUF files from a source you trust and keep Vulkan-capable graphics drivers current.
- Project scaffolds use known deterministic templates, require write approval, are assembled transactionally inside the workspace, and refuse to overwrite existing destinations.
- Web assets are disabled until exact hosts are allow-listed. Only HTTPS URLs without credentials or nonstandard ports and passive image/audio/OBJ/GLB extensions are accepted. Redirects and proxies are disabled, and the connection is pinned to a DNS result that passed local/private/link-local address rejection.
- Asset bytes are streamed into a project quarantine with a configured size limit. Redirects are disabled; an optional publisher SHA-256 is verified; source, licence, actual hash, size, and timestamp are written to a sidecar manifest.
- Staging is not importing. Inspection is read-only and verifies a strict manifest, exact byte count and SHA-256 plus bounded structure for PNG, JPEG, WebP, WAV, Ogg, MP3, OBJ, and GLB. External OBJ material libraries and all GLB URI references are rejected.
- Import is a separate `Write` approval bound to the exact inspected SHA-256, selected project, unchanged filename, and destination. It re-inspects and rehashes while copying, uses atomic no-overwrite moves, writes a licence/provenance sidecar, and retains quarantine. Archives, executables, Unity packages, Blender files, scripts, authenticated stores, and automatic purchases are not supported.
- `.forgecore` is reserved for internal backups, quarantine, and metadata. General write, patch, scaffold, and build targets cannot point into it.
- Text patches require an exact unique old selection, are limited to 1 MiB files and 100,000-character replacement sides, support optimistic SHA-256 checking, snapshot before replacement, and use a same-directory temporary file.
- Snapshot rollback accepts only existing `.bak` files under `.forgecore/backups`, requires the expected current SHA-256, and snapshots the pre-restore version.
- Dedicated .NET actions accept only `.csproj`, `.sln`, or `.slnx` paths and `Debug`/`Release`. Restore is supplied only an empty workspace-local package feed, so ordinary NuGet acquisition is disabled. MSBuild projects and targets are executable content and are not OS-network-sandboxed; review unfamiliar projects before approval. Processes have bounded output and time and are killed as a tree on cancellation.
- Project indexing is read-permission only and cannot target outside the workspace or `.forgecore`. Recursive scanning does not follow reparse points and excludes build/cache/internal directories, binary/unsupported/oversized files, `.env`, app settings, launch settings, and filenames containing secret, credential, or password markers.
- The index database stores no source bodies or string-literal values. It stores paths, hashes, sizes, timestamps, extracted declaration names, and identifier terms under configurable file-count/per-file/aggregate limits. Replacement is transactional, so cancellation does not destroy the prior index.
- Index search never authorizes an edit and clearly reports snapshot age. The current file must still be read through the secured workspace tool, and every later write remains separately validated and approved.
- Online catalogue search is disabled unless configured and always derives `Network` permission. The only v0.7 catalogue endpoint is the fixed Openverse HTTPS API; redirects and proxies are disabled, local/private/link-local destinations are rejected, and query/result/response/cache limits are enforced.
- Catalogue results accept only CC0/public-domain or commercial/derivative-compatible `CC BY`/`CC BY-SA` metadata, exclude mature and non-HTTPS records, preserve source/licence/attribution links, and are explicitly labelled untrusted. A result is not a licence guarantee; the user must review its source page before staging.
- Raw catalogue payloads exist only in the current planning loop and bounded process-memory cache. SQLite stores a redaction marker instead of the payload, and the durable assistant transcript omits the raw result block. User queries and the model's concise final summary remain part of local conversation history.
- The Seele and Meshy adapters use fixed HTTPS API origins through the hardened no-proxy/no-redirect public-network client. Tasks have exact identity, bounded JSON, polling intervals and timeout; cancellation stops local polling/downloads. Meshy uses a fixed Meshy 6 preview followed by a linked PBR refine and selects only the refined GLB. Only GLB and bounded passive preview images may be staged. Signed artifact query strings/fragments are removed from durable provenance.
- Cloud-generated output is never imported automatically. It is staged transactionally with a SHA-256 manifest and a provider-specific `*_GENERATED_REVIEW_REQUIRED` marker, structurally inspected, and still requires a separately approved exact-hash import. Archives, packages, scripts, Unity projects, executables, and ambiguous downloads are rejected.
- Unity actions are denied unless `UnityEditorPath` identifies an existing local `Unity.exe`, `UnityEditorVersion` exactly matches `ProjectSettings/ProjectVersion.txt`, the target has Unity's required project shape, and the bundled bridge is installed. ForgeCore never installs Unity, upgrades a project through a mismatched configured Editor, activates licences, stores Unity credentials, or runs the Editor as administrator.
- The Unity bridge and map-kit sources are deterministic and version/hash-bound. Installation never overwrites. Each Editor action has a strict operation-specific schema, requires `Execute` approval or matching bounded session authorization, uses no shell, and is constrained by project paths, request SHA-256, protocol/result identity, timeout, bounded output, cancellation, and process-tree termination.
- Unity Package Manager is either disabled with `-noUpm`, or restricted to a configured locked-local mode. Locked-local mode requires pinned direct dependencies already present under `Library/PackageCache`, preserves exact manifest/lock bytes, and restores both files before failing if Unity mutates them. It does not authorize package acquisition or installation.
- Unity scene creation and Windows builds refuse existing targets. Scene creation snapshots existing Build Settings before registering the new scene; primitive/component scene mutations also create local `.forgecore/unity/backups` snapshots first. Build output is restricted to `Builds/.../*.exe`; external outputs and existing `.exe`/`_Data` pairs are denied.
- Generated-asset preparation accepts only an imported `.glb` under `Assets/ForgeCore/Generated` with its exact imported provenance sidecar and SHA-256. The executor revalidates destination, review marker, byte count and streaming hash; the bridge independently rechecks the hash, requires a preinstalled GLB importer, uses exact scene/anchor/object names, bounds target height and collider mode, creates a protected scene backup, and never overwrites an existing object.
- Trusted-project mode may pre-authorize this typed preparation only after normal policy validation and only inside its exact project/time/action budget. It never includes cloud spending, package/software installation, publishing, credentials, legal/rights acceptance, deletion, arbitrary commands, administrator actions, unknown licences, or access outside the workspace.
- Unity project scripts, Editor scripts, asset importers, tests, and build callbacks are executable content and are not OS-network-sandboxed. They can do more than the typed request describes. Review unfamiliar project code before approval and do not open the same project simultaneously in another Editor instance.
- Unity MCP is disabled by default. Discovery/calls require the official Assistant package declaration, exact local relay, matching Editor version, workspace project, ForgeCore approval, and Unity's first-connection approval in the intended Editor. Calls use an exact case-sensitive tool allow-list; wildcards and arbitrary relay arguments are unsupported.
- MCP tool descriptions and results are untrusted. Requests/results are bounded, malformed or incompatible JSON-RPC is rejected, timeouts/cancellation kill the relay process tree, and Unity credentials/tokens are never read or persisted. A permitted Unity tool can still execute project/Editor code or reach Unity services as the normal user; only allow tools whose schema and effects you understand.

## Trust boundary

Model output is untrusted data. A generated `ToolCall` has no authority until the security policy validates it and, where required, the user approves it. Tool implementations repeat boundary checks before accessing the filesystem.

## Known limits

This release does not provide general web search, semantic embeddings, source-body indexing, OS sandboxing, encrypted memory, broad Windows automation, browser credentials, elevated actions, archive/package inspection, Unity/package installation, licence activation, registry access, unrestricted command execution, automatic model acquisition, or automatic Unity generative-service configuration. The official MCP relay path and deterministic Frontier Valley workflow have live acceptance on the configured Unity `6000.5.5f1` project. The Seele and Meshy clients and quarantine path have automated contract tests; a new provider/account still requires an informed live acceptance run. These checks do not prove the safety, rights, or quality of generated content or unfamiliar projects.
