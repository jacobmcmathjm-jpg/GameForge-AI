## What is implemented

ForgeCore can now create one original bounded **technical mannequin** in installed offline Blender, retain its editable source and materials, import the exact skinned GLB, and test that actual Unity import in a fresh diagnostic scene. This is a narrow rigging recipe, not arbitrary realistic character generation.

Use the new app prompt:

```text
Create a rigged mannequin in Blender. Name it training-enemy.
```

The deterministic route proposes five separately scoped actions: create/exact-source reuse, hash-verified non-overwriting import, exact bridge install/upgrade, Unity compile, and `inspect_character_rig`. It does not use a language model or paid service, silently download an asset, modify an existing gameplay enemy, manufacture human approval or place the mannequin into a live level.

- Recipe `rigged_humanoid_v1` accepts only an existing project, bounded lowercase asset name, seed 0–999999 and height 1600–2000 mm. Static barrel radius, arbitrary Python, input files, output paths and URLs are rejected. The internal retained request has a compatibility radius field fixed at zero, not a character parameter.
- Original continuous voxel-unioned suit/mitten/head mesh; 22 named bones, at most four normalized influences per vertex, UVs and three original PBR materials with 512px source images. Hands have no finger rig and the head has an opaque visor, not a detailed face.
- One explicit **Generic named-bone** convention: `generic_named_bones_v1`, T rest pose, Blender -Y forward/+Z up, exported Unity +Z forward/+Y up, metres, identity root transforms and grounded feet. No valid Unity Humanoid avatar, retargeting compatibility or motion clips are claimed. Root motion is in-place with no motion clips.
- Immutable source bundles retain `.blend`, self-contained GLB, three packed/source PNGs, studio preview, measured metrics, `rig.json`, exact request and recipe. Bundle entry and all files are hash/length verified before reuse/import; arbitrary old recipe hashes are not accepted as current source.
- The dense GLB skin parser validates named joints/hierarchy, embedded bounds/encodings, inverse-bind count/finite values, actual JOINTS/WEIGHTS arrays, finite bounded positions and normalized weights. General compressed/sparse/more-than-four-influence skin imports are not added by this recipe.
- Unity bridge 0.17.16 independently checks real `SkinnedMeshRenderer` weights, bone/bind mappings, readable mesh, material slots/shaders, canonical dimensions, baked rest geometry, three diagnostic poses and restoration. Fresh scene/PNG destinations and exact GLB/provenance/metadata protection remain mandatory. Evidence is local and separate from the reviewed-art vault.

Passing this gate is not anatomy, art or production animation certification.
