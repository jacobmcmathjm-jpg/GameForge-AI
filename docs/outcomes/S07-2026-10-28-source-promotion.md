# S07 — source-only promotion and bounded suitability

Status: **Technical subset implemented; S07, real human acceptance and target-game readiness remain open.** This continues the approved next step after the source-review interface. It is an app update, not a graphics or game-content change.

## Implemented

- `CheckLocalBlenderCompatibility` is read-only. It fully verifies the exact immutable source bundle and checks bounded role, implemented recipe, rig requirement, source height and triangle budget. It reports source coordinates/bounds, materials, map resolution and zero source clips honestly. Target Unity inspection is still required; animation compatibility is explicitly `not_measured_in_target`.
- `PromoteLocalBlenderAsset` is a separate scoped write. Its proposal binds all five source identity hashes plus the exact current approved visual and rights review-record hashes. Missing, rejected, invalid, stale or exhausted review evidence blocks execution. No fabricated licence, human attestation or implicit import/placement follows.
- Immutable source-only promotion versions live separately under `.forgecore/blender-library/approved/<source-bundle>/<promotion-hash>/entry.json`. Their content address binds source, recipe/Blender identity, measured metadata and both reviews. The existing `.forgecore/asset-vault` Unity-evidence admission rules, including its provenance rules, are unchanged. These two tiers must not be conflated.
- Existing editable source objects and prior decisions/versions are never rewritten. Identical requests verify/reuse the same version. New review records make old promotions stale; rejection revokes current usability. Search reports promotion state separately while target visual/rights/placement flags stay false. Damaged/oversized history fails closed.
- Source review writes and promotion share an in-process gate plus a create-only cross-process lease. A stale/occupied lease is a stop, not silently erased. New promotion metadata is staged, source/reviews are revalidated and publication is an atomic directory move. Cancellation before commit publishes no approved version; failed staging is not blindly replayed. Human attestations retain the existing live-only/non-recoverable gate.
- Exact offline prompts: `Check local Blender asset <64-character bundle hash>.` and `Promote local Blender asset <hash>.` Unsupported syntax never falls through to an inference model/provider. Search/review routes remain separate; neither promotion nor compatibility triggers creation, Unity/Blender or a game edit.
