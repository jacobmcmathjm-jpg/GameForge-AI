### Changes and interpretation

- A shared, Unity-compatible C#9 collector is compiled by Core tests and embedded verbatim (normalized LF) into the generated runtime. It adds phase counts, mean/maximum, >33.334/100/250/1,000 ms counts, GC collection deltas and managed/Unity-allocated memory context. It keeps the first **64** timestamped long frames, a dropped count and a separate worst event, even if the worst occurs after the cap. Normal-frame collection performs no JSON/log/file I/O; instrumentation overhead is not independently benchmarked.
- `startup` is **Unity-clock initialization latency**, with a before-scene runtime marker and zero invented rendered-frame samples. Native process startup before that clock/marker is unobserved. Host runner wall time separately includes process start and shutdown, not a fabricated native startup duration.
- Warmup stays exactly **one second**. Phase ownership is by observation end; a frame crossing its boundary is still included in the existing gameplay distribution and 100 ms gate. Event starts are explicitly **inferred as realtime end minus Unity unscaled delta**, not independently traced GPU/CPU frame starts. Startup-spanning frames can therefore be attributed to warmup or gameplay with explicit crossing flags. Do not add phase averages/durations as non-overlapping frame totals.
- GC/memory snapshots span consecutive `Update` observations, not necessarily the same inferred unscaled-delta interval. They are correlation/context only, not proof that GC, shaders or I/O caused a stall. No cause is assigned from zero or nonzero collection deltas.
- Player request/result schema is now **3**; saved evidence is **4**. The host rejects missing/inconsistent/oversized/malformed phase evidence rather than backfilling old results. The measured-window p95/GPU/memory/100 ms rules are not relaxed; `wholeSessionSmoothnessAccepted` remains explicitly false, including when only warmup is slow. Startup/warmup acceptance budgets remain unestablished.
- Wire shape is checked before typed deserialization, including required fields, duplicate names and bounded arrays; field initializers cannot invent omitted evidence. Only Unity's fully present all-default absent-worst-event class sentinel is normalized to null when the recorded long-frame count is zero. Raw bytes/hashes remain unchanged. Both retained real results were revalidated read-only with this final validator; no new players were started.
- Every new profile keeps its request/result, runner observation and hashes, including failures/timeouts. Old evidence is untouched. A bounded runner observation is written even when the runner does not return normally. Result input remains capped at 1 MiB, total observed samples at 1,000,000 and long-frame detail at 64 plus worst. The sampler fails/stops rather than silently discarding overflow/invalid intervals.
- Candidate kit **0.16.35**, bridge unchanged **0.17.15**. Exact-hash protected upgrades recognize .33 and the retained .34 candidate. The first .34 live compile failed on a duplicate generated local variable; its source backup, failed receipt and log are retained. .35 corrects the generated variable without changing gameplay or acceptance thresholds. `Verify-S01Source` now semantically compiles generated Runtime/Editor sources against installed Unity references before relying on a host build.
