# S08–S10 industrial kit, gated source manifest and mission prototype

Started 28 October 2026; resumed 29 October 2026. Work in progress; human art/rights, approved target placement, full combat playthrough and balance acceptance remain open.

## What this changes in ForgeCore

The reusable offline implementation—not a one-off externally generated game—now includes five fixed original Blender recipes, a typed industrial asset manifest/source-import gate, and an authored industrial infiltration greybox mission builder. These are bounded recipes and one mission profile, not unrestricted Blender modelling or arbitrary finished-game generation.

S08 sources retain editable `.blend`, metre-scale grounded transforms, UVs, four 1K PBR maps, three independently exported GLB LODs and conservative collision metadata. Unity preparation creates a separate measured prefab/review scene; it does not approve art. Fence collision is solid despite its open visible mesh. Containers are sealed, with no walkable interior.

S09 planning is read-only and shows every unmet requirement. Source-set import requires five exact, current, live human visual/rights review pairs and source promotions. It rechecks a deterministic manifest hash, preflights fresh destinations, and retains a no-replay import journal. Source promotion is not target Unity acceptance. **Automatic approved target placement is not implemented in this increment**; the manifest explicitly reports it unavailable.

S10 provides three ordered interactions (restore power → retrieve shipping manifest → extract), two gated encounters using three existing original security guards, conservative cover/boundaries, route/spawn checks and pause/death/reset. Its ten industrial prop slots remain explicitly labelled greyboxes. Unreviewed new source props are not silently placed into the game as accepted art.

## Bounded offline prompts

- `Create an industrial barrel in Blender. Name it yard-barrel.`
- `Create a wooden crate in Blender. Name it supply-crate.`
- `Create a concrete barrier in Blender. Name it low-cover.`
- `Create an industrial fence in Blender. Name it yard-fence.`
- `Create a shipping container in Blender. Name it cargo-box.`
- `Plan industrial assets for yard-mission.`
- `Import reviewed industrial assets for yard-mission.`
- `Create an industrial infiltration mission in Blender. Name it yard-mission.`

The final prompt reuses or creates the fixed security character through Blender; Unity authors the skeletal clips, weapon, mission logic and scene. It does not mean Blender independently designs an entire realistic game. Source generation, import and editor operations remain separately scoped. Unsupported syntax does not become arbitrary script execution.

### Mission test route

From the starting area, reach the power kiosk at X −10 / Z −9 and press **E** within 2 m. Clear the two service-yard guards, reach the manifest kiosk at X −10 / Z 9 and press E. Clear the extraction guard, then reach X 10 / Z 13 and press E to finish. The on-screen objective changes with encounter progress. WASD/mouse, Shift sprint, Space jump, LMB fire, hold RMB sights, R reload, Esc pause and F5 reset are retained. Clearing the last guard alone is not a win; extraction is still required.

Technical tests are separate from human visual/motion/balance acceptance. Scripted route tests use actual CharacterController movement at 30/60/120 Hz but directly apply guard damage to isolate progression gates; they are not a representative combat playthrough. A short player startup test is not a soak test or performance certification.

Known prior issue remains open: the general `PrototypeFeedback.Burst` particle effect does not explicitly assign a particle material and can appear magenta. This increment does not claim to resolve it.
